`latest`는 개발 중 빠르게 확인하기에는 편하지만 어떤 소스에서 만들어진 이미지인지 설명하지 못한다. 노드에 이미지가 캐시되어 있으면 기대와 다른 버전이 실행되는 상황도 생긴다.

## 세 가지 태그만 사용한다

블로그 이미지에는 다음 태그를 게시한다.

- `sha-<commit>`: 모든 main 브랜치 빌드에 붙는 변경 불가능한 식별자
- `1.2.3`: 릴리스에 붙는 사람이 읽기 쉬운 버전
- `latest`: 현재 main의 편의용 포인터

실제 Kubernetes Deployment에는 SHA 또는 SemVer 태그를 사용한다. `latest`는 사람이 이미지를 빠르게 실행해 보는 용도로만 남긴다.

```yaml
image: ghcr.io/maackia/blog:sha-a1b2c3d
imagePullPolicy: IfNotPresent
```

## 롤백도 선언으로 남긴다

문제가 생기면 이전 이미지 태그로 Deployment를 수정한다. 과거 이미지가 같은 이름으로 덮어써지지 않으므로 롤백 결과가 예측 가능하다.

이 단순한 규칙만으로도 "지금 실행 중인 코드는 무엇인가"라는 운영 질문에 빠르게 답할 수 있다.
